# Миграция с хостингового голосового провайдера

Эти гайды сопоставляют понятия и API трёх провайдеров, с которых чаще всего уходят игровые
команды, с их эквивалентами в Aurix, перечисляют, что вы приобретаете и что теряете, и дают
порядок миграции, при котором игроки всё время остаются на связи. Подробные таблицы соответствий
по каждому провайдеру — на английском:

| Откуда | Гайд |
| --- | --- |
| Unity Vivox (Unity Gaming Services) / Vivox Core SDK | [Vivox → Aurix](../migration/vivox.md) |
| Agora Voice SDK (RTC) | [Agora → Aurix](../migration/agora.md) |
| Photon Voice (PUN 2 / Fusion / Quantum) | [Photon Voice → Aurix](../migration/photon-voice.md) |

> Имена API вендоров взяты из их публичной документации на момент написания и служат только
> ориентирами; точные сигнатуры сверяйте с актуальным справочником провайдера. Имена Aurix
> сверены с кодом и OpenAPI-контрактом этого репозитория.

## Что одинаково везде

Каждый гайд делает одни и те же три хода, потому что у трёх провайдеров одна и та же форма:

1. **Credentials выпускает ваш бэкенд, клиент держит только короткоживущий токен.** Vivox
   Access Tokens, RTC-токены Agora и custom authentication Photon кладут секрет на ваш сервер,
   а токен — на устройство. В Aurix так же: **API-ключ** (`aurx_…`) остаётся на бэкенде и
   выпускает **JWT игрокам** (`POST /v1/tokens`), в которых перечислены каналы и права в них.
   [Server SDKs and token servers](../backend/server-sdks.md) содержат готовый token-эндпоинт на
   Node, Python, Go и C#; [модель угроз](threat-model.md) объясняет, что эта граница защищает.
2. **Канал — это канал.** Каналы Vivox, каналы/комнаты Agora и interest groups Photon становятся
   **каналами** Aurix с `channel_type` (`team`, `positional`, `command`, `whisper`, `echo`) и
   JSON-`config` ([Channels and audio routing](../features/channels.md)). Ad-hoc каналы
   (`{"ad_hoc": {"name": "match-8f3a", …}}` в гранте токена) заменяют API «войти по имени»:
   канал появляется при первом входе и исчезает с последним игроком.
3. **Модерация переезжает на бэкенд или в подписанные одноразовые токены.** У провайдеров либо
   есть server-to-server API (Vivox, Agora), либо это оставлено игровому коду (Photon). В Aurix
   есть `POST /v1/moderation/{mute,kick,ban,…}` для бэкенда и одноразовые **action-токены**
   (`kick`/`mute`/`unmute`) для модераторов в игре — клиент никогда не сможет перенаправить
   модерирующее действие ([Moderation](../features/moderation.md)).

## Что меняется для вашей команды эксплуатации

Теперь провайдер — вы. Конкретно это значит держать (или платить тому, кто держит):

* одну или несколько нод `aurix-server` на регион, PostgreSQL и Redis
  ([Deployment](../operations/deployment.md), [Scaling out](../operations/scaling.md));
* TURN для игроков за симметричным NAT — встроенный `[turn]` или свой
  ([Deployment → Network and firewall](../operations/deployment.md#network-and-firewall));
* HA control plane — Redis Sentinel или Cluster и реплики PostgreSQL
  ([High availability](../operations/high-availability.md));
* метрики и алерты ([Backups and observability](../operations/observability.md));
* обновления ([Releases and versioning](../operations/releases.md)).

В Aurix есть CI с chaos-набором (убийство ноды, failover Redis Sentinel, рестарт PostgreSQL),
фаззинг парсеров, подписанные релизы и SBOM, но **нет** глобальной anycast-сети, статус-страницы
и контракта поддержки. Прочитайте [Ограничения](limitations.md) — там честно перечислено, что не
проверялось за пределами CI этого репозитория (реальные консоли, WebGL-плееры, масштаб WAN).

Наличие функций — по публичным спискам вендоров и этому репозиторию. «✓» у Aurix значит
«реализовано и покрыто тестами здесь», а не «сравнено с вендором в бенчмарке».

| | Vivox | Agora Voice | Photon Voice | Aurix |
| --- | :-: | :-: | :-: | :-: |
| Self-hosted / исходники | – | – | – (Photon Server for Voice — отдельная лицензия) | ✓ сервер AGPL-3.0, SDK Apache-2.0 |
| Позиционный (3D) голос | ✓ | ✓ (расширение spatial audio) | через `AudioSource` движка | ✓ серверное затухание + HRTF в клиенте / спатиализация движком |
| Потоки на участника для спатиализации движком | – (микс канала) | ✓ | ✓ | ✓ PCM в native/Unity/Unreal/Godot, треки в браузере |
| Большие каналы (слушатели, серверный микс, лимит потоков) | ✓ | ✓ (роль audience) | interest groups | ✓ |
| Текстовый чат | ✓ | отдельный продукт | отдельный продукт | ✓ (lite: канал, личные, история, read-маркеры) |
| Серверный API модерации | ✓ | ✓ | – | ✓ REST + action-токены + вебхуки |
| Запись | – (сторонние) | ✓ cloud recording | – | ✓ Ogg/Opus, с согласием, mixdown, S3 |
| STT / TTS / перевод | STT ✓, TTS ✓ | через расширения | – | ✓ подключаемые провайдеры |
| Сквозное шифрование | – | шифрование медиа общим ключом | шифрование транспорта | ✓ групповое E2EE (sender keys) native + браузер |
| Reconnect / resume / failover | ✓ | ✓ | ✓ | ✓ resume + takeover на другой ноде |
| Web / браузерный клиент | ✓ | ✓ | – | ✓ WebRTC SDK + Unity WebGL + Godot Web |
| Unity / Unreal / Godot | ✓ / ✓ / – | ✓ / ✓ / – | ✓ / – / – | ✓ / ✓ (не компилируется в этом CI) / ✓ |
| Консоли | ✓ | ✓ | ✓ (Unity) | гайд по портированию поверх C ABI, бинарников нет |

## Порядок миграции, при котором игроки не теряют голос

1. Поднимите staging-ноду и пройдите [быстрый старт](quick-start.md) до конца — две вкладки
   браузера разговаривают. Закладывайте полдня вместе с PostgreSQL/Redis.
2. Добавьте token-эндпоинт Aurix рядом с существующим (token-серверы в `sdk/server/*/examples`
   — шаблон). Идентичность берётся из *вашей* сессии, никогда из тела запроса.
3. Перенесите один тип каналов под feature-флагом — обычно party/squad — и выкатите во
   внутреннюю сборку. Сравните: задержку входа, потери/джиттер на ваших тестовых сетях, CPU на
   самом слабом поддерживаемом устройстве.
4. Перенесите позиционные каналы и модерацию; подключите вебхуки `participant.*` /
   `moderation.*` туда, что раньше потребляло колбэки вендора.
5. Канарейка по региону или по когорте; держите SDK вендора в сборке, пока канарейка не пройдёт
   через пик. Aurix и вендор могут сосуществовать — ничто в Aurix не захватывает аудиоустройство
   эксклюзивно.
6. Удалите SDK вендора, отзовите секреты вендора из бэкенда.
